# 車検のLLM意味理解優先化

対象：車検2シナリオ。ローカル実装、未公開。

## 修正

固定ルールで質問を認識してから候補を限定する構造を、主要な質問では顧客設定に合う候補を先に提供する構造へ変更。LLMの話題と候補の対応、原文引用、最後の回答対象、登録音声、現在の顧客設定を確認して採用する。連絡先の未知表現を後段のキーワード判定で「はい」に戻さない。履歴の判定記録に意味判定採用の経路を残す。

LLM利用不可・保留・不正選択時は既存ルールを使用。「走行距離はおわかりになりますか」も予備ルールで認識する。先行する予約処理をフォールバックに移し、最後の具体的質問をLLMが先に理解できるようにした。

## 検証

- 新規62条件：距離3設定×工程3段階×言い回し6種、OFF・保留・通信例外・候補外・話題不一致・前半引用、前半話題の拒否、異なる距離音声の拒否。本番のaddMessage/commitMessageを使用し、採用音声の存在と更新状態も確認。
- 既存47テストを回帰確認。旧4項目LLM出力の互換テストで問題を検出し、answerTargetがない場合も原文evidenceが最後の対象に一致するときだけ受理するよう修正。テストの期待値は変更していない。
- 実LLM：既存公開APIに架空発話3件と修正後ローカル候補を送信。3件すべてLLM選択IDと最終音声IDが一致、非常代替なし。

## 限界と戻し方

マイク認識・実機での音声試聴は未検証。実LLM3件は全表現の正解を保証しない。予約・引取などの専用状態遷移は既存処理を維持し、12カ月点検の会話制御は変更していない。API側のプロンプト、採点、音声ファイル、Firestoreは変更なし。

変更は作業ブランチfix/nov8-llm-semantic-primaryに隔離。公開版は未変更。取り消す場合はこの変更のapp.js差分と新規テスト・文書だけを戻し、既存の未追跡ファイルは保持する。
