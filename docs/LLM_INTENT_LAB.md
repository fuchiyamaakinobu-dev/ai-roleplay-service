# 12カ月点検のLLM判定比較

## 追加：ロープレへの返答連携（2026-10-13）

起動後 http://127.0.0.1:4318/roleplay/ を開く。「LLMで言い換えを理解する」をONにし、12カ月点検を選択、検証用の社員コード`000000`で開始する。「一緒に済ませておきたい整備はありますか？」を送ると、LLMが認識した場合、登録済みMP3の「オイル交換もお願いします。」へ進む。

対象は冒頭の追加作業・車両状態確認だけ。音声の新規生成はしない。採点は従来のままなので、LLMだけが認識した発言は加点されない。1日50回・30秒間隔の上限は比較画面と共通。チェックを外すと従来処理になる。

この画面ではローカル標準シナリオを使い、Firestore履歴へ送信・保存待ち登録をしない。公開版とは別の検証用。実APIで言い換えから登録済み返答への接続を確認済みだが、全場面の品質やマイクの動作を保証する検証ではない。

## 確定：今回の検証範囲（2026-10-13）

ユーザーの段階導入指示により、点検以外の作業希望と車両状態の確認を、既存ルールと外部LLMで比較する独立した検証画面を追加した。既存のapp.js、シナリオ、採点、MP3、公開サイトには接続しない。初期状態は外部送信OFF。

この画面は単一発話の判定を比較する。会話全体の採点ではない。通常アプリの別々の発話を合算する既存仕様は維持する。LLMのyes/no/uncertainと、yesの根拠となる原文の連続引用を検証する。原文の引用が正しくても意味の正しさは保証されないため、人が比較する。

## 起動

Node.js 22以降を使用。追加パッケージは不要。リポジトリのフォルダで実行する。

```powershell
node lab/server.mjs
```

ブラウザで http://127.0.0.1:4318 を開く。キー未設定でも既存ルールの判定を試せる。サーバーはこのPCからだけ接続できる。終了は端末でCtrl+C。

## Groq無料プランの接続

1. GroqコンソールでFree Planであることと、モデル利用可否・組織の制限を確認する。有料プランには切り替えない。
2. `lab/.env.example`をリポジトリ直下の`.env.local`としてコピーし、ローカルのエディターでGROQ_API_KEYを設定する。チャットにキーを貼らない。
3. 無料プラン確認後に`LLM_LAB_FREE_PLAN_CONFIRMED=true`とする。これは運用上の確認フラグであり、APIで契約を自動確認する機能ではない。
4. `node --env-file=.env.local lab/server.mjs`で再起動する。
5. 画面で外部送信のチェックを入れ、架空の例文で1件ずつ比較する。氏名や社員コード、会話履歴、音声データは自動取得・送信しない。入力した文章だけを送る。

LLMはGroqの`qwen/qwen3.8-27b`、推論OFF、出力320トークン上限。2026-10-13時点の提供元資料でプレビュー扱いのため、正式採用は未確定。日本語の接客判定精度は実APIで未検証。モデル廃止・利用不可時は判定失敗として表示し、別の有料モデルへ自動変更しない。

## 使用量と失敗時

- この検証環境では日本時間で1日50回、30秒間隔、同時1件。失敗したリクエストも回数に含める。
- `.llm-lab/budget.json`に回数と時刻だけを保存し、再起動しても保持する。破損時は外部送信を停止する。カウンタを削除して上限回避しない。
- 6秒で中断。自動リトライなし。APIが429を返したら、この検証環境からの送信を24時間休止する。
- 回数制限は無料を保証するものではない。同じ組織の別アプリの利用やトークン制限もある。費用を防ぐ前提は提供元のFree Planで運用すること。
- キーと無料プラン確認の両方がない場合は呼び出さない。キー、LLMの生応答、入力文はサーバーログへ出さない。
- 検証用ページだけを配信する許可リスト、同一Origin検証、ループバック限定待受を採用。公開インターネット向け認証を備えたサーバーではない。

## 検証手順

例文の標準的な質問、言い換え、症状だけ、作業希望だけ、両方、単なる言及、言いかけを比較する。正解はdocs/EVALUATION_RULES.mdとSERVICE_FLOW.mdを基準に人が確認する。判断保留や不一致を正解として自動採用しない。

```powershell
node qa/check-llm-intent-lab.mjs
```

自動テストは代替のAPI応答を使用して通信経路・制限・出力検証を試す。LLMの日本語精度の証明ではない。

## 確定：2026-10-13 ローカルでの返答・MP3候補選択

前節の未知表現だけの分類を拡張し、12カ月点検の受付〜引取希望では、登録済みMP3の候補IDをLLMが選ぶ。スタッフ発言（600文字以内）、直近4発話、進行状況、許可候補をGroqへ送る。初期OFF。顧客の役柄は引取希望。時間説明済みなら時間を聞き直す候補を除き、未説明なら引取候補を除く。選択IDは適用直前にも検証する。候補外出力・通信失敗・判断保留時は既存ルールに戻る。

返答選択は15秒間隔、比較画面は30秒間隔、合計1日50回のローカル上限。既存判定で認識済みの発言も対象段階では候補選択に送る。採点は従来処理のまま。引取希望後と車検2シナリオは既存処理。Firestoreには保存せず、公開アプリへの反映は未実施。

実API・画面検証で「オイル交換を含めて作業時間は60分、一時間かからない程度で終わりますが、店舗でお待ちいただけますでしょうか。」に対し「出来れば車を取りに来てもらえませんか？」を約0.31秒で選択し、引取依頼へ進んだ。これは1例の成功であり、全発話の正解や実マイクの認識精度を保証しない。
