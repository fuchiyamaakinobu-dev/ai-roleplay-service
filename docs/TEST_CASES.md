# テストケース

## 自動テストとして固定すべき基準

### 共通

- シナリオの配点合計が100点
- 進行チェックは初期値ONで、OFFにすると上部の確認項目と現在の段階を隠す
- 進行チェックの表示設定をブラウザーに保存し、会話進行・採点・音声へ影響させない
- 発話完了判定時間を0.5秒・0.8秒・1秒・1.5秒・2秒から選択でき、初期値1.5秒と選択値をブラウザーへ保存する
- 音声認識の最終結果後、自動送信までの待機に発話完了判定時間の選択値を使用する
- 確認済み、対応中、再確認必要、対象外を実際の判定結果に連動して表示する
- 車検誘致では工程表示と別に、お客様の「必要な発話」と「確認できた発話」を固定領域へ表示する
- 必要な発話は現在以降の基本発話を表示し、確認できた発話は実際の会話ログにあるお客様発話を時系列で表示する
- 進行チェックをOFFにするとお客様発話チェックも非表示になり、会話進行・採点には影響しない
- 車検誘致では「佐藤様／ヤリス／車検満了日9月30日／8月1日以降作業可能」を画面上部へ固定表示する
- 進行チェックをOFFにしても車検誘致のお客様情報は表示し、12カ月点検では非表示にする
- 6桁の数字でない社員コードではロープレを開始しない
- 全角の6桁数字は半角へ正規化して受け付ける
- ロープレ開始時に社員コード、日時、シナリオを開始履歴へ保存する
- 採点時に社員コード、点数、評価、所要時間、会話ログを1回だけ保存する
- 履歴保存の成否は会話進行と得点計算に影響させない
- 実施履歴は管理者だけが閲覧でき、社員コード・シナリオで絞り込める
- 管理者が実施履歴画面を開くと、採点結果と開始履歴がそれぞれ最新500件に整理される
- CSVへ実施日時、社員コード、シナリオ、点数、所要時間、評価を出力できる
- 表示文と音声登録文が一致
- `ready`音声ファイルが存在し、極端に小さくない
- まこと（カスタマーサポート）の車検誘致用お客様音声40件と、呼び出し音1件が存在

### 12カ月点検

- 追加整備未確認でも減点して会話継続
- 作業時間と追加整備確認を同じ発話で認識
- 「調子の悪いところや気になる点はありませんか」だけでも、お客様が「オイル交換もお願いします」と返答する
- 点検以外のご用命だけを質問しても「オイル交換もお願いします」と返答する
- 点検以外のご用命と気になる点を別々の発話で確認しても、両方を会話履歴へ保持して達成とする
- 車両状態だけを質問し、点検以外のご用命を確認していない場合は確認項目を満点扱いにしない
- 「オイル交換もお願いします」と回答
- 再確認時は「そのほかは大丈夫です」と回答
- 作業時間を説明済みなら同じ質問を繰り返さない
- 「作業時間は確認します」「まだ分かりません」「1時間では終わりません」「1時間半」を1時間説明として認識しない
- 作業時間質問へ想定外の回答をした場合、引取依頼へ進まず、直前と異なる作業時間質問へ言い換える
- 仕事が理由のお客様へ「お仕事がお休みの時に来店できますか」と確認した場合、想定外の聞き返しをせず「土日なら行けるかもしれません」と答えて日時確認へ進む
- 確認漏れや不十分な説明があっても、会話が成立していれば未達項目として減点し、日時確認など次の工程へ進む
- 「必ず来店してください」などの押しつけ、または「車の引き取りはできません」などの明確な拒否があった場合だけ「おっしゃっていることがよく分からないんですけど」と返す
- 「その時間帯は対応できません」など、引取と無関係な対応不可は引取拒否として誤判定しない
- 来店提案中に入庫日時を確定した後で追加整備を確認しても、日時確認へ戻らない
- 作業時間を先に説明し、日時確定後にもう一度説明しても、作業時間や日時を再質問しない
- 作業時間説明後にオイル交換を受け付け、時間を再案内しない場合は、会話を止めず作業時間を未達とする
- 作業時間説明後にオイル交換を受け付け、「追加作業を含めても1時間程度」または「作業時間に変更はありません」と再案内すれば達成とする
- オイル交換を含めて1時間と再案内した後、次の発話が希望日の確認だけでも作業時間を再質問せず引取依頼へ進む
- オイル交換追加後に時間を再案内しない場合も、作業時間を再質問せず、再確認必要の未達状態を残して引取依頼へ進む
- 作業時間説明後にオイル交換を受け付けると「時間説明」を再確認必要で表示し、再案内後は確認済みに戻す
- オイル交換を先に受け付け、その後で作業時間を説明した場合は、再案内なしで達成とする
- 引取理由が仕事なら土日・時間帯提案に反応
- 日付だけなら時間帯を聞き返す
- 日付と時間がそろうと予約確定
- 11時と15時のように複数の時刻を提示した場合、お客様が「では、早いほうでお願いします」と返答してから予約確定
- 日付確定後に具体的な時刻を1つ提示した場合、「では、その時間でお願いします」と返答してその時刻を確定
- 複数の具体的な時刻を提示した場合、早い時刻または遅い時刻を選択し、表示文に対応する時刻を確定
- 午前・午後だけを尋ねられ、日付も未確定の場合、「午前中がいいです。今週だと何日が空いていますか？」と返答
- 「日曜日の午前中」または日付確定後の「午前中はいかがですか？」には、「では、午前中でお願いします。何時が空いていますか？」と返答し、具体的な時刻を待つ
- 日付確定後の「午前中が空いています」には、「では、午前中でお願いします。何時が空いていますか？」と返答する
- 「午前中は空いていません」「午前中の空きはありません」などの否定表現を午前中の提案として認識しない
- 「午前中ですと10時、お昼からですと４時に空きがあります」を10時・16時の2候補として認識する
- 「1時間」を予約時刻の1時として認識せず、「作業に1日かかる」を入庫日として認識しない
- 「8月20日の10時は空いていません」を予約候補として確定せず、「土日にご来店できませんか」は肯定的な提案として認識する
- 全角数字の時刻を認識し、「午後」「お昼から」に続く1時から11時を午後の時刻として比較する
- 「お昼一時はいかがでしょうか」を13時の単一候補として認識し、「では、その時間でお願いします」と返答する
- 漢数字の「一時」を具体的な時刻として認識する一方、「一時間」は予約時刻として誤認識しない
- 午後1時から5時を13時から17時へ変換し、「午後４時」と「16時」は同一候補として扱う
- 午前中の具体的な時刻確認を繰り返す場合、「何時が空いていますか？」「午前中の何時が空いていますか？」へ言い換える
- 日時不足、内容不明、車検誘致の必須項目不足で、同じ質問文を連続発話しない
- 質問を言い換えても、必須の日付・時刻が未確定なら勝手に会話を先へ進めない
- 日時確認候補を使い切った後も、直前と同じお客様発話を連続表示しない
- 「では、早いほうでお願いします」、説明の食い違い解消後、家族相談後の再連絡、近い店舗・家族来店への同意、汎用の会話継続で登録済みMP3を再生
- 「午前」「午後」だけでは具体的な時刻未確定として会話継続
- 引取を即時確定すると減点
- 引取理由の回答として家族相談をランダム表示しない
- 達成済みの追加整備確認を「次回の改善トーク」へ含めない
- 「畑がお忙しいのですね」「お仕事で来店が難しいのですね」で引取事情の受け止めを達成する
- 「平日のご来店は難しいですね」のように、お客様固有の事情を含まない一般的な説明だけでは引取事情の受け止めを達成しない
- 未達が引取事情の受け止めだけなら、理由の深掘り質問ではなく事情を受け止める改善トークを表示する
- 全項目達成時は、改善指摘ではなく現在の流れを継続する案内を表示する
- 仕事理由では不要な他店舗提案なしでも満点にできる
- 距離・運転不安では不要な土日提案を満点条件にしない
- 距離・運転不安のお客様発話は特定店舗名を含めず、「お店には行けません」と表示文・音声登録文を統一する
- 距離・運転不安のお客様に「買い物のついで」だけを提案しても日時確認へ進まず、近い店舗または家族との来店を提案するまで事情を伝え直す
- 「土日は営業していません」「夕方は対応できません」「近い店舗はありません」「家族との来店は難しいです」を肯定的な代替案として認識しない
- 来店方法への同意前に提示された日付・時刻を予約確定として保持せず、「では、その日にお願いします」と誤って終話しない
- Firestoreの古い12カ月点検データに無効化済み発話や音声ID数の不一致が残っていても、登録済みready音声だけへ候補をそろえる

### 車検誘致

- 「さとう」「しゃけん」「だいしゃ」「そうこうきょり」「にもつ」「じばいせき」「れんらく」など主要語がひらがなで認識されても、漢字・カタカナ表記と同じ判定結果になる
- 「くがつさんじゅうにち」「はちがつついたち」「じゅうじ」「いちじかんじゅうごふん」のような月日・時刻・分数のひらがな数詞を、判定時だけ具体値へ補正する
- 判定用のひらがな補正を会話表示・保存ログの発話原文には適用しない
- 「ごじつ」を「5時」と誤補正しない
- ロープレ開始ボタンを押すと、呼び出し音の後に「はい、もしもし。」が再生され、その終了後に音声認識がONになる
- 呼び出し音は会話ログにお客様発話として表示せず、「はい、もしもし。」だけを最初のお客様発話として表示する
- 「もしもし」だけでは本人確認ステップを進めない
- 「お客様でしょうか」だけでは本人確認を達成しない
- 「トヨタです」だけでは店舗・担当者名を達成しない
- 「トヨタモビリティ帯広の渕山ともうします」は音声認識上の「申します」の表記揺れとして名乗りを達成し、「どちら様でしょうか？」を返さない
- 「とよたもびりてぃおびひろのふちやまともうします」のように店舗名・担当者名・語尾がひらがなへ変換されても名乗りを達成する
- 「渕山ともうします」のように店舗名がない場合、または「トヨタモビリティ帯広です」のように担当者名がない場合は名乗りを達成しない
- お客様名の本人確認を省略して店舗名・担当者名を名乗った場合は、「どちらにおかけですか？」と聞き返さず、「お世話になっております。」と応答して次へ進む
- 本人確認を省略した場合は本人確認4点を未達とするが、聞き返し減点は付けない
- 本人確認も名乗りも確認できない場合は「どちら様でしょうか？」と名乗りを求める
- 本人確認と名乗りをまとめて話しても認識
- 挨拶、本人確認、名乗り、日頃のお礼、走行距離、追加作業、予約手続き時間などが未確認でも、具体的な月日と時刻を提案した場合は過去工程へ戻らず日時調整へ進む
- 入庫日時確定後は、待ち方、荷物・持参品、ロックナット、10分または15分前来店、3日前連絡、予約復唱が未確認でも同じ内容を聞き直さず終話できる
- 入庫日時確定後、気になる症状を省略して持参品・ロックナット・早めの来店・3日前連絡・連絡先をまとめて案内した場合、過去工程へ戻らず「この携帯にお願いします」と返答する
- 入庫日時確定後にスタッフが「ありがとうございました」と終話した場合、AIお客様もお礼を返してそのまま終了する
- 月日だけ、または時刻だけの場合は終話条件を満たさず、不足する日時だけを聞き返す
- 名乗りと「いつもお世話になっております」をまとめて話すと、減点条件を保ったまま車検案内へ進む
- 日頃の利用へのお礼なしでも減点して進行
- 「よろしければこのお電話でご予約できますが、いかがでしょうか」を都合確認として認識し、「お願いします。」または「お願いしようと思っていました。」と返答して次へ進む
- 「車検の方はお決まりでしたでしょうか」「車検はもう決められましたか」を都合確認として認識し、「こちらこそ。」で止まらず予約希望の肯定返答へ進む
- 音声認識結果が「やりす」「ヤリす」でも「ヤリス」として車検時期案内を判定する
- 質問ではない「車検は決まりました」だけでは都合確認を達成しない
- 車種・車検時期、具体的な満了日、電話予約提案を同じ発話で案内した場合も、「はい。」ではなく予約への肯定返答を優先する
- 質問ではない「この電話で予約できます」だけでは都合確認を達成しない
- 通常の「ご都合はいかがでしょうか」には、従来の「お願いしたいんですけど、いつできますか？」を維持する
- 本人確認と店舗・担当者名の名乗りを達成すれば、お礼が未達でも進行チェック「本人確認・名乗り」は確認済みになる
- お礼がない場合は「こちらこそ」ではなく「はい」と返す
- 「もう少しお時間ありますか」「お時間をいただいてもよろしいですか」「このまま予約を進めてもよろしいですか」で予約手続き確認を達成する
- 「よろしければご予約をいただければと思いますが、いかがでしょうか」で予約手続き確認を達成し、「今、このまま予約できますか？」を繰り返さず日時調整へ進む
- 車検期限など前工程が未確認でも、「予約のお電話に15分程度お時間がかかりますがよろしいでしょうか」と質問した場合は「車検はいつまでですか？」へ戻らず、「大丈夫ですよ。」と回答して日時調整へ進む
- 上記で省略した前工程は未達のまま採点し、案内不足の聞き返し減点を付けない
- 会話冒頭の一般的な「もう少しお時間ありますか」だけでは、予約手続き確認まで大幅に工程を飛ばさない
- 「予約手続きに10分かかります」のように質問・了承確認がない説明だけでは予約手続き確認を達成しない
- 予約手続き時間の了承確認を省略して「8月20日はいかがでしょうか」と日付を提案した場合、了承確認は未達のまま日時調整へ進み、「何時が空いていますか？」と時刻だけを確認する
- 予約手続き時間の了承確認を省略して「土曜日、何時ぐらいからご都合よろしいでしょうか」と曜日・希望時間帯を質問した場合、前工程へ戻らず「午前中でお願いします。何日の予定ですか？」と回答する
- 「土曜日に改めてお電話します」のような質問ではない曜日の言及は、予約日時調整の開始として誤認識しない
- 予約手続き時間の了承確認を省略して「ご都合なんですが、いつぐらいとかご希望ありますでしょうか」と質問した場合、前工程へ戻らず登録済み音声の「お願いしたいんですけど、いつできますか？」で空き日を確認する
- 「ご希望の日にちはございますか」「希望の日程を教えてください」も希望日の質問として認識し、「具体的な日時を教えてください。」とは回答しない
- 「いつもありがとうございます。ほかにご希望はありますか」のような日程と無関係な希望確認は、日時調整開始として誤認識しない
- 予約手続き時間の了承確認を省略して「平日と土日ではどちらがよろしいでしょうか」と質問した場合、前工程へ戻らず既存音声の「土日がいいです。」と回答する
- 「来週の火曜日ではいかがでしょうか」に「土日がいいです。」と回答した後、同じ月の文脈で「9日土曜日はいかがでしょうか」と提案された場合は「何時が空いていますか？」と返答し、曜日希望を繰り返さない
- 「8月1日以降」の後に提示された「9日土曜日」は8月9日として保持し、その後に「10時」が提示されれば8月9日10時として予約日時を確定する
- 上記の分岐では「今、このまま予約できますか？」へ戻らず、案内不足の聞き返し減点を付けない
- 日付だけの提案を保持し、次のスタッフ発話で具体的な時刻が提示されれば月日と時刻を合わせて予約日時を確定する
- 車検満了日を具体的に案内すれば、入庫可能日の案内がなくても満了日項目を達成する
- 「9月30日までとなります」のように「車検」「満了」を省略しても、登録済み満了日と一致すれば達成し、期限を再質問しない
- 「8月1日までとなります」のように登録済み満了日と異なる日付は達成せず、期限を確認する
- 入庫可能日だけを案内し、車検満了日がない場合は達成しない
- 車検満了日の案内が不足した場合、お客様は最初に「車検はいつまでですか？」と尋ねる
- 同じ不足が続いた場合は「いつまでに受けなきゃダメですか？」と言い換え、「車検の満了日はいつですか？」とは発話しない
- 案内不足が続いても、AIお客様は「必要な内容がまだ確認できていません」などの評価者視点の文章を発話しない
- 車検誘致の聞き返しでは、音声IDのない「すみません、〜」などを自動生成せず、登録済みの「まこと」MP3がある発話だけを使用する
- 案内不足の警告は会話欄外へ表示し、従来どおり聞き返し回数に応じて減点する
