# プロジェクト仕様

最終確認日: 2026-07-28

## 確定: 目的

自動車販売店スタッフが、お客様役との音声またはテキスト会話を通じて応対を練習し、会話後に採点と改善点を確認できるWebアプリとする。

## 確定: 現在の対象シナリオ

1. 12カ月点検・来店促進
2. 車検誘致・電話フォロー
3. 車検誘致・引取納車対応

現在のコードに車両販売シナリオは存在しない。車両販売編は`docs/SALES_FLOW.md`で未確定として管理する。

## 確定: 現在の提供機能

- お客様発話の表示と音声再生
- AIお客様の反応速度設定（スタッフの発話完了判定と返答開始待ちを共通設定で調整、0.5秒・0.8秒・1秒・1.5秒・2秒、初期値1.5秒、ブラウザー保存）
- スタッフの音声認識またはテキスト入力
- 状態遷移とキーワード判定による会話進行
- 画面上部へ固定する確認項目の進捗表示と表示ON/OFF
- 車検誘致17採点項目の判定語・言い換え・不足例・音声認識補正を検索できる判定単語帳
- 車検誘致の会話ログで、採点条件を満たしたスタッフの判定語を緑、一部だけ認識した判定語を黄色で表示（項目名はツールチップで確認可能）
- 車検誘致では、お客様名・車種・車検満了日・作業可能日を画面上部へ固定表示
- シナリオ別の採点、改善点、推奨トーク
- A4縦・白黒を前提とした会話と評価の印刷
- 6桁の社員コードによる実施者識別
- ロープレ開始履歴、点数、評価、会話ログのFirestore保存
- 管理者専用の実施履歴一覧、絞り込み、CSV出力
- Google管理者ログインによるシナリオの下書き保存と公開
- Firestore公開データが取得できない場合のローカルデータ利用

「車検誘致・引取納車対応」は、安定稼働中の通常車検シナリオを複製して分離した応用編とする。通常車検の判定は変更せず、お客様の引取希望後だけ、理由確認、事情の受け止め、理由に合う来店案、選択肢保持、来店日時または引取場所・日時の具体化を追加判定する。来店が難しく引取希望が続く場合は、希望を拒否せず自宅などの引取場所を確認して予約へ進む。

車検誘致のお客様情報は進捗表示とは別の参照情報とし、進捗表示をOFFにしても表示する。シナリオを切り替えた場合は、選択中のシナリオデータに合わせて表示または非表示を更新する。

## 確定：2026-10-14 荷物案内への連絡先誤応答を防止

画像の「トランクの荷物を降ろしてご来店ください」に対し「この携帯にお願いします」が出る経路を調査。既存処理は両車検シナリオの持参品・到着・連絡先工程で「分かりました」を返した。LLM候補に連絡先回答が無条件で存在し、そのIDを返す代替LLMで誤応答が再現した。実際の当該応答のLLMログは保持していないため、過去の選択そのものは断定しない。

修正：質問ではない案内は質問用候補をLLMへ送らない。連絡先候補は現在の最後の質問が連絡先確認の場合だけ作成し、適用直前にも再検証する。前の連絡先質問が履歴にあっても荷物案内では携帯返答を拒否。荷物案内の後に連絡先質問が続く複合発話では正しい候補を保持する。音声・採点は変更しない。

### 2026-10-14 車検LLMの質問別候補制限

車検上級・応用の候補生成は現在の最後の質問を用い、走行距離・作業希望・連絡先・引取理由・引取場所ごとに対象音声を絞る。引取場所の質問から連絡先・返却先を除外する。職場引取の記憶がある場合は自宅音声を候補にしない。適用時にも同じ候補条件で再検証する。該当候補がない場合は既存処理へ戻す。採点根拠は従来どおりスタッフの原文のみ。

## 確定：2026-10-15 LLM意味判断と返答チェック

ローカル候補選択はidだけでなくkind（質問/依頼/説明/相づち/判断不能）、topic、原文の連続部分evidenceを必須とする。根拠が原文にない出力は拒否。話題と候補の音声種別、質問専用音声と発話種別の不一致はruleへ戻し、拒否したIDを返す。同一通信で処理し追加API呼出しは行わない。既存の候補生成範囲・採点・MP3は維持する。LLMが意味自体を誤判定する可能性は残る。

ローカル画面の「返答チェック」にスタッフ原文、LLM分類、根拠、選択ID、採用経路、実際の返答と音声ID、再生開始/失敗を表示。直近20件をメモリのみ保持し、更新または消去ボタンで消える。対象外・利用間隔制限などの既存処理経路も区別する。再生開始はブラウザのplayingイベントであり人間の実聴取確認ではない。

## 確定：2026-10-16 名前間違いへの本人確認音声

ユーザー指示により、車検誘致の上級・応用の電話冒頭で、正しいお客様名と異なる名前を呼んで本人確認した場合に限り2音声を再登録する。名乗り前は「どちらにおかけですか？」、名乗り後は「はい、どちらにおかけですか？」。使用停止の一律制限はこの用途について更新する。本人確認を省略しただけの場合は従来どおり聞き返さず進む。

正しい顧客名・会話状態から誤名候補を制限し、LLMはidentityとして候補IDを選ぶ。適用直前にも再確認する。通信失敗・OFF・制限・保留でも明確な誤名には同じ音声で応答。誤名発話では進行・達成・予約を更新せず、訂正後は従来の本人確認へ戻る。既に本人確認済み、予約済み、引取相談中、電話冒頭を過ぎた場合はこの専用分岐を使わない。12カ月点検は対象外。
## 確定：2026-10-16 店内待機・引取の二択への返答

車検誘致応用で「店内で待つか、それとも引取か」と明示的に選択を求められた場合は、既存の引取希望音声で回答する。多走行距離の預かり説明が未完でも、相づちにせず引取希望を先に伝えて理由確認へ進む。説明不足は原発話の既存採点で判定し、二択への回答だけで達成にしない。

LLMへは専用候補を渡し、保留・OFF・通信失敗・利用制限でも同じ専用処理へ戻る。既に来店・引取で合意済み、予約確定済みの場合や、最後の質問が別の話題の場合はこの分岐で後退させない。引取理由の記憶を再質問で消さない。
